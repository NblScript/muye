## Slide 2：问题背景

### 传统农业害虫防治的四大痛点

| 痛点 | 现状 | 后果 |
|------|------|------|
| **识别慢** | 依赖人工田间巡查 | 发现害虫时已错过最佳防治期 |
| **决策粗** | 凭经验用药，缺乏数据支撑 | 用药过量或药不对症，农药残留高 |
| **审核缺** | 无系统性安全校验 | 高毒农药误用、天气不适宜时强行作业 |
| **执行难** | 人工背负式喷洒 | 效率低、人员暴露风险、覆盖不均匀 |

> 数据参考：我国每年农药使用量约 30 万吨，利用率仅 40% 左右，过量用药问题突出。

## Slide 3：系统愿景

### 一句话定位

**牧野是一套从害虫识别到无人机精准施药的端到端 AI 管线，让 AI 替农户做"查、判、审、打"四件事。**

```
害虫检测（查） → 气象采集 → AI 决策（判） → 合规审核（审） → 无人机精准施药（打）
```

### 设计原则

- **AI 闭环**：检测结果驱动航线规划，实现变量喷洒
- **安全优先**：五项合规检查 + 三级拦截，杜绝高毒农药误用
- **一键展示**：单机（WSL2）环境完整运行，无需云部署

## Slide 6：技术创新 ① — 多智能体会诊

### 问题

单一 LLM 可能因训练数据偏差导致推荐不当，缺乏多角度交叉验证。

### 方案

三个专家角色并行推理，从不同维度评估害虫防治方案：

| 专家角色 | LLM 提供商 | 评估维度 | 权重 |
|---------|-----------|---------|------|
| 昆虫学家 | 千问 (Qwen) | 虫害识别准确性、防治时机 | 40% |
| 农学家 | DeepSeek | 作物生长阶段、农事建议 | 35% |
| 植保专家 | 小米 MiMo | 农药安全性、施药规范 | 25% |

### 路由优化

- 系统先评估场景熟悉度（40% 农药匹配 + 25% 历史案例 + 20% 相似度 + 15% 候选评分）
- 熟悉场景 → 专家快速路径（单模型，低延迟）
- 陌生场景 → 多智能体会诊（三模型并行，高可靠性）
- 专家路径失败时自动升级到会诊，确保鲁棒性

## Slide 7：技术创新 ② — 农药安全合规推理链

### 问题

AI 推荐的农药可能存在毒性过高、作物不匹配、天气不适宜等安全隐患，缺乏系统性审核。

### 方案 — 五项检查串行审核

```
AI 推荐农药
    │
    ▼
 ① source_match ── 农药是否来自可信目录？
    │
    ▼
 ② crop_match ── 当前作物是否在适用范围内？
    │
    ▼
 ③ pest_match ── 防治对象是否覆盖检测到的害虫？
    │
    ▼
 ④ toxicity_risk ── 毒性等级是否安全？（高毒→拦截）
    │
    ▼
 ⑤ weather_risk ── 风速/湿度是否适合施药？
    │
    ▼
 三级执行策略:
 · passed  → 自动执行
 · warning → 强制人工确认
 · blocked → 拦截 + 推荐替代农药
```

### 亮点

- 每项检查携带**证据链**（来源 + 匹配字段），可追溯、可审计
- 被拦截时自动从 80 条农药目录中推荐**低毒替代方案**（最多 3 条）
- 天气约束：风速 ≥8m/s 直接拦截，湿度异常触发风险提示

## Slide 8：技术创新 ③ — 密度感知变量喷洒

### 问题

传统无人机均匀喷洒，所有区域药量相同。虫害分布不均匀时，高密度区药量不足，低密度区浪费农药。

### 方案 — 检测驱动的变量喷洒

```
YOLO 检测结果（bbox 位置）
        │
        ▼
   密度图计算（8×10 网格）
   将检测框中心映射到农田坐标
   累加置信度 → 归一化密度 0~1
        │
        ▼
   变量喷洒规划
   ┌───────────────────────────────┐
   │ 密度 ≥ 0.6（高密度）→ 喷量 ×1.5 │
   │ 密度 0.3~0.6（中等）→ 喷量 ×1.0 │
   │ 密度 < 0.3（低密度）→ 喷量 ×0.5 │
   └───────────────────────────────┘
        │
        ▼
   前端展示：昆虫相对热力图 + 变量喷洒路线
```

### 效果

- 形成**检测 → 密度分析 → 变量施药**的完整 AI 闭环
- 高密度区精准加量，低密度区节省农药，预计可减少 30% 用药量
- 前端热力图实时展示虫害分布与喷洒强度

## Slide 11：系统可靠性设计

### 容错机制

| 场景 | 处理策略 | 用户体验 |
|------|---------|---------|
| RAG 不可用 | 降级为无知识增强决策 | 警告提示，流程不中断 |
| LLM 调用失败 | 指数退避重试（最多 3 次） | 无感知 |
| 专家路径失败 | 自动升级到多智能体会诊 | 橙色"升级"徽章 |
| 高毒农药 | 合规链直接拦截 | 禁止起飞 + 推荐替代 |
| PX4 不可用 | 动画仿真模式替代 | 前端正常展示 |
| 网络中断 | HTTP 轮询降级 WebSocket | 自动切换 |

## 附录：评委可能提问的预备答案

**Q: 系统的决策准确率如何保证？**
> 三重保障：(1) RAG 从 80 条农药演示种子中检索候选，并保留来源字段；(2) 三模型并行会诊 + 加权投票，减少单一模型偏差；(3) 合规推理链五项检查兜底，任何不匹配都会拦截或降级。生产使用前仍需接入权威登记数据并由农艺人员复核。

**Q: 变量喷洒实际效果如何？**
> 基于 YOLO 检测的 bbox 位置构建默认 8×10 网格，并按本次任务最大网格权重归一化。高热值区喷量提升 50%、低热值区减少 50%，形成检测→热力分析→变量施药的 AI 闭环。该热值用于任务内相对分布展示，不代表绝对虫口密度。

**Q: 系统在真实场景中如何部署？**
> 两种模式：(1) 竞赛展示：WSL2 单机一键启动；(2) 扩展部署：后端 API 与前端可独立部署，PX4 通过 MAVSDK real 链路连接 SITL 或兼容真机。DJI OSDK 当前只完成后端接口和仿真适配，Matrice 实机通信待开发与验收。

**Q: 合规推理链的数据来源？**
> 当前仓库随附 80 条用于演示和规则验证的农药种子，覆盖 7 类目标作物；这些数据不等同于可直接用于生产的权威登记库。天气可接入和风天气实时 API，知识库还包含施药天气指南、安全间隔期参考等仓库文档。生产使用前必须接入权威登记数据并完成专业复核。
