# 牧野智农——智慧农业害虫防治系统 参赛材料

---

## 一、作品简介

**作品名称**：牧野智农——智慧农业害虫防治系统

**作品简介**：

牧野智农是一套面向智慧农业植保场景的端到端智能作业指挥系统。系统围绕"虫情感知、气象感知、智能决策、农药安全合规审计、无人机精准施药、效果评估闭环"构建完整业务闭环，实现从农田图片输入到害虫识别、施药方案生成、安全合规审核、无人机航线规划与执行的全流程自动化。

系统包含四大核心能力模块：

1. **害虫检测模块**：基于 YOLOv8 目标检测模型，对上传的农田图片进行害虫识别，输出害虫种类、置信度和位置信息，并据此生成单次任务内的昆虫相对热力图，驱动变量喷洒航线规划。

2. **智能决策模块**：结合害虫检测结果、实时气象数据和 RAG 农业知识库（含 80 条农药演示种子，以及构建时从仓库文档动态切分的知识块），通过决策路由自动选择专家路径或多智能体会诊路径，生成包含用药方案、农事建议和安全间隔期的结构化防治建议。

3. **农药安全合规推理链**：在决策输出与无人机执行之间设置五项串行安全检查（来源校验、作物匹配、害虫匹配、毒性风险评估、天气风险校验），将合规结果分为"自动通过""人工确认""拦截执行"三级，确保用药安全可控。被拦截时自动从农药目录中推荐低毒替代方案。

4. **无人机精准施药模块**：基于昆虫相对热力图生成变量喷洒航线，高热值区域提高喷洒速率、低热值区域降低喷洒速率，支持 PX4 动画演示和 MAVSDK real 执行，并保留 DJI OSDK 后端接口与仿真适配。喷洒完成后自动调度复检，评估防治效果，若杀灭率未达标则自动进入下一轮喷洒，形成完整的"检测→决策→执行→评估→复喷"任务闭环。DJI OSDK 实机通信尚未完成，不作为当前成果宣称。

系统前端采用 React + TypeScript 构建暗色主题指挥大屏，实时展示识别结果、天气信息、决策过程、合规推理链、昆虫相对热力图、无人机状态和任务历史，并通过 WebSocket 实现状态实时推送。

系统后端采用 FastAPI 构建异步 API 服务，通过 JSONL 事件总线实现模块间松耦合通信，SQLite 进行结构化数据持久化，ChromaDB 向量数据库支撑 RAG 知识检索，整体架构层次清晰、可扩展性强。

## 五、设计思路

### 1. 问题分析

我国是农业大国，农业病虫害每年造成显著的粮食产量损失。传统植保方式面临四大问题：

- **发现慢**：依赖人工田间巡查，发现害虫时往往已错过最佳防治期
- **决策粗**：凭经验用药，缺乏气象、作物、农药知识等多源数据支撑，导致用药过量或药不对症
- **审核缺**：缺少系统性的农药安全校验环节，存在高毒农药误用、天气不适宜时强行作业的风险
- **执行难**：人工背负式喷洒效率低、覆盖不均匀，作业人员存在健康暴露风险

针对以上问题，本作品提出了一套"感知→决策→审核→执行→评估"的端到端智慧植保系统方案。

### 2. 总体设计理念

系统设计遵循"安全优先、闭环可控、可解释可追溯"三大原则：

**安全优先**：AI 决策不直接驱动无人机执行，中间设置农药安全合规推理链作为安全闸门。任何用药方案必须通过五项安全检查才能进入执行环节，高毒农药或不适宜天气条件下系统会自动拦截并推荐替代方案。

**闭环可控**：系统不是一次性喷洒工具，而是构建了"检测→决策→合规→执行→评估→复喷"的任务闭环。喷洒完成后自动调度复检，量化防治效果，若杀灭率未达标则自动进入下一轮作业，直到防治目标达成或达到最大迭代次数。

**可解释可追溯**：合规推理链的每一项检查都携带证据链（数据来源、匹配字段、判定依据），决策过程通过多专家会诊投票机制提供多角度解释，所有任务数据通过 SQLite 结构化存储和 JSONL 事件流持久化，支持历史检索和复盘。

### 3. 架构设计

系统采用前后端分离、领域模块化的分层架构：

```
┌──────────────────────────────────────────────┐
│              前端展示层（React + Vite）         │
│         指挥大屏 · 地图态势 · 任务面板          │
├──────────────────────────────────────────────┤
│              应用层（FastAPI）                  │
│   工作流编排 · 事件驱动管线 · SLO 监控          │
├──────────────────────────────────────────────┤
│            核心业务层（领域模块化）               │
│  detection/  decision/  drone/  infra/        │
├──────────────────────────────────────────────┤
│            数据模型层（Pydantic + SQLAlchemy）   │
├──────────────────────────────────────────────┤
│    数据层（SQLite + JSONL + ChromaDB）          │
└──────────────────────────────────────────────┘
```

各层之间通过严格的依赖规则解耦：
- 领域模块之间不直接调用，跨域通信统一通过事件总线
- 核心业务逻辑不依赖应用框架细节
- 数据模型独立定义，作为前后端接口的统一边界

### 4. 核心流程设计

系统核心处理管线设计为 8 个阶段：

```
图片输入 → 害虫检测 → 气象采集 → RAG 知识检索 → 智能决策 → 合规审核 → 航线规划 → 无人机执行
                                                                         ↓
                                                    效果评估 ← 复检检测 ← 等待药效
                                                                         ↓
                                                        达标 → 任务完成
                                                       未达标 → 下一轮喷洒
```

每个阶段的输出既是下一阶段的输入，也会通过事件总线推送到前端实时展示，形成可观测的处理管线。

### 5. 前端设计

前端采用暗色主题指挥大屏风格，使用 Three.js 渲染单块虚拟田地（不依赖外部地图服务），适合竞赛场景下的稳定展示。界面布局分为：
- 顶部操作栏：运行模式指示、图片上传、演示控制
- 左侧信息区：天气、检测统计、无人机状态
- 中央地图区：单田地态势、相对热力图、飞行路径
- 右侧决策区：检测结果、用药方案、合规推理链、会诊面板
- 底部流程条：管线各阶段实时进度

通过 HTTP 轮询 + WebSocket 双模式实现状态实时推送，WebSocket 不可用时自动降级为轮询。

## 六、设计重点与难点

### 重点一：多源异构数据的融合决策

**问题**：害虫防治决策需要同时考虑害虫种类、气象条件、农药知识、作物类型和历史经验等多种异构数据源，数据格式不统一，时效性要求不同。

**解决方案**：设计统一的决策上下文结构，将 YOLO 检测结果（结构化 JSON）、和风天气数据（REST API 响应）、RAG 知识检索结果（向量相似度文档）和 SQLite 历史记录（关系型数据）统一聚合为结构化 prompt 输入。每类数据通过独立的适配模块转换，决策引擎只面对统一格式的上下文，不感知底层数据源差异。

### 重点二：农药安全合规的五项串行检查

**问题**：AI 模型可能输出不安全的用药建议（如高毒农药、作物不匹配、天气不适宜），如果直接进入执行环节会造成实际危害。

**解决方案**：设计合规推理链，在决策输出和执行环节之间设置五项串行安全检查，采用"断路器"模式：任何一项检查返回 blocked 状态即终止执行流程，同时自动从 80 条农药目录中检索最多 3 条低毒替代方案推荐给操作人员。每项检查均携带证据链（数据来源、匹配字段），实现可审计的安全控制。

### 重点三：密度感知的变量喷洒航线规划

**问题**：传统无人机均匀喷洒不考虑虫害空间分布差异，高密度区域药量不足导致防治效果差，低密度区域药量过剩造成浪费和污染。

**解决方案**：将 YOLO 检测结果的 bbox 中心映射到田地网格（默认 8×10），累加各网格的检测置信度并按本次任务最大网格权重归一化，生成相对热力图。航线规划器根据相对热值生成变量喷洒调度表：热值≥0.6 的区域喷量提升至 1.5 倍，热值<0.3 的区域喷量降至 0.5 倍。前端将网格边界归一化到 Three.js 虚拟田地，以红/琥珀/绿三色呈现相对分布与喷洒强度；该热值不等同于绝对虫口密度。

### 重点四：从决策到执行的安全闸门机制

**问题**：在 AI 系统直接控制物理设备（无人机）的场景下，如何确保人类始终保留最终控制权，防止误操作。

**解决方案**：设计人工确认起飞机制。系统默认采用 manual 模式——AI 决策完成后发布 pending_confirmation 事件，前端显示"确认起飞"按钮，必须由操作人员手动点击确认后系统才会启动无人机执行。合规推理链的 warning 状态也会触发人工确认流程，确保高风险操作始终有人类把关。

### 难点一：事件驱动的跨域松耦合通信

**难点描述**：系统包含检测、决策、无人机、基础设施等多个业务域，模块间存在数据依赖（如检测结果驱动决策，决策结果驱动航线规划），但直接函数调用会导致紧耦合，不利于独立开发和测试。

**解决思路**：引入 JSONL 文件事件总线作为跨域通信的唯一通道。各模块只发布和订阅事件，不直接调用其他模块的接口。事件以 JSON 格式写入文件，同时满足实时推送（前端轮询）和持久化追溯（历史查询）需求。这种设计使每个业务域可以独立开发和测试，也使系统具备事件回放和状态恢复能力。

### 难点二：多模型协同决策的编排与容错

**难点描述**：三个不同的大模型并行推理时，需要处理调用超时、部分失败、输出格式不一致和结果冲突等复杂情况。

**解决思路**：设计决策路由层和会诊编排器。路由层先评估场景熟悉度（综合农药匹配、历史案例、相似度等指标），熟悉场景走单模型快速路径降低延迟，陌生场景走多模型会诊提高可靠性。会诊编排器对三个模型并行调用，支持指数退避重试（仅重试 5xx 和网络错误，4xx 不重试），单个模型失败时其余模型继续投票。最终通过加权投票机制汇总结果，并计算置信度和分歧度。

### 难点三：任务闭环的异步状态管理

**难点描述**：喷洒后的效果评估需要等待药效期（数小时到数天），期间系统需要维持异步状态、管理定时复检、处理多轮迭代，并保证后台任务在系统异常时不会丢失。

**解决思路**：基于 asyncio.Task 实现异步任务管理。喷洒完成后自动创建评估任务并注册到后台任务列表参与优雅关闭，使用 SQLite 的 missions 和 mission_iterations 表持久化任务状态。复检定时器到期后重新调用 YOLO 检测，对比前后害虫数量计算杀灭率。所有异步任务都有对应的数据库状态记录，即使系统重启也能从数据库恢复任务进度。

### 难点五：前后端实时状态同步

**难点描述**：后端处理管线包含多个异步阶段（检测、决策、合规、执行），前端需要实时反映每个阶段的状态变化，同时处理 WebSocket 连接不稳定的情况。

**解决思路**：采用 WebSocket 优先 + HTTP 轮询降级的双模式策略。后端通过事件总线将每个阶段的状态变更写入 JSONL 文件，WebSocket 连接正常时实时推送事件，连接断开时前端自动切换为 HTTP 轮询模式拉取最新事件。前端工作流面板通过统一的 useDashboardState Hook 管理所有状态，对上层组件屏蔽数据获取方式的差异。

### AI 在作品中的应用说明

本作品将人工智能技术应用于以下环节，实现了从感知到执行的智能化处理：

**应用一：害虫智能检测（YOLOv8 目标检测）**

- 基于 IP102 害虫数据集（102 类害虫、75000+ 张图像）训练 YOLOv8 目标检测模型
- 对上传的农田图片进行实时推理，输出害虫种类（如蚜虫、稻飞虱、玉米螟等）、检测置信度和边界框位置
- 检测结果同时用于生成本次任务内的昆虫相对热力图，驱动变量喷洒航线规划
- 检测模型封装为独立 API 服务，支持模型热切换（运行时更换不同权重文件）

**应用二：智能防治决策（大语言模型多智能体会诊）**

- 系统将害虫检测结果、实时气象数据、RAG 知识检索结果整合为结构化上下文
- 通过决策路由层评估场景熟悉度，自动选择决策路径：
  - 熟悉场景：调用单一专家模型快速生成建议（约 3 秒）
  - 陌生场景：触发三模型并行会诊，三个大模型分别扮演"昆虫学家""农学家""植保专家"角色，从不同专业维度独立评估防治方案，通过加权投票机制（权重 40%/35%/25%）汇总最终建议（约 10 秒）
- 专家路径失败时自动升级为多模型会诊，保证决策总能产出
- 大模型调用支持指数退避重试机制，应对网络波动和服务器瞬时故障

**应用三：知识检索增强（RAG 向量检索）**

- 构建农业知识向量库，包含 80 条农药演示种子、从当前仓库文档动态切分的知识块和持续增长的历史决策案例
- 每次决策前自动进行语义检索，将相关的农药推荐、施药指南和历史案例拼接到决策上下文中
- 检索失败时自动降级为基础决策模式，不阻塞主流程
- 每次决策完成后自动将新案例增量写入向量库，系统在使用过程中持续积累经验

**应用四：农药安全合规推理（规则引擎 + 知识库校验）**

- AI 决策输出的用药方案不直接进入执行，而是通过五项串行安全检查进行合规审核
- 检查内容涵盖农药来源校验、作物适用性匹配、防治对象匹配、毒性等级评估和天气条件校验
- 合规结果分为"自动通过""需人工确认""拦截执行"三级，高风险方案直接拦截并自动推荐低毒替代农药
- 每项检查携带证据链（数据来源、匹配字段），实现可审计的安全控制

**应用五：防治效果评估闭环（检测模型复用）**

- 无人机喷洒完成后，系统根据决策输出的预计见效时间自动调度复检
- 复检时再次调用 YOLO 检测模型，对比喷洒前后害虫数量，计算杀灭率
- 若杀灭率未达到 90% 阈值，系统自动进入下一轮喷洒-复检-评估循环（最多 3 轮）
- 评估结论和任务经验自动写入知识库，供后续决策检索参考
