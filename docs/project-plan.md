# 牧野智能农业害虫防治系统项目计划书

## 一、项目概述

### 1. 项目名称

牧野智能农业害虫防治系统。

### 2. 项目定位

牧野是一个面向智慧农业植保场景的端到端智能作业指挥系统。项目围绕“虫情感知、气象感知、AI 决策、农药安全合规审计、真实无人机接入、飞行仿真、大屏可视化、任务追溯”构建完整闭环，既能服务竞赛现场展示，也具备继续扩展为真实农业作业平台的工程基础。

项目不是单一的害虫识别模型，也不是简单的大屏动画展示，而是将图像识别、农业知识库、大模型决策、农药安全规则、DJI Matrice 300 RTK 真实无人机接入、PX4 SITL 飞行仿真、任务报告和可视化指挥统一到一条可运行、可解释、可追溯的业务链路中。

### 3. 项目愿景

项目希望探索一种更安全、更智能、更可落地的智慧植保工作方式：系统先通过图像识别发现虫情，再结合天气、作物、农药知识和历史案例生成防治方案，随后通过农药安全合规推理链审计风险，最后驱动无人机执行或进入人工确认。通过这种方式，AI 不再只是生成文本建议，而是参与到一个受约束、可审计、可执行的农业作业流程中。

### 4. 建设目标

- 建设害虫图像识别能力，实现农田虫情自动感知。
- 建设 RAG 农药知识库，使 AI 决策具备农业知识依据。
- 建设多专家 AI 会诊能力，提高防治建议的可靠性和可解释性。
- 建设农药安全合规推理链，在无人机执行前审计用药风险。
- 建设 DJI Matrice 300 RTK 真实无人机接入能力，实现仿真与真机统一控制架构。
- 建设 PX4 SITL 飞行仿真链路，保障竞赛现场稳定展示。
- 建设可视化指挥大屏，展示识别、决策、合规、飞行和任务状态。
- 建设任务记录与报告生成能力，实现作业过程可追溯、可复盘。

## 二、项目背景与意义

### 1. 农业病虫害防治现状

农业病虫害防治直接影响粮食产量、农产品质量和农业生产成本。传统植保工作通常依赖人工巡田、经验判断和人工施药，存在发现不及时、判断不准确、作业效率低、记录不完整等问题。在大面积农田场景中，人工巡检难以及时覆盖全部区域，虫害早期症状容易被忽略，等到肉眼明显可见时往往已经造成扩散。

随着无人机、边缘计算、人工智能和农业信息化的发展，植保作业正在从“人工经验驱动”转向“数据感知与智能决策驱动”。无人机可以快速覆盖农田区域，图像识别模型可以辅助发现虫情，大模型可以帮助生成防治建议，知识库可以提供农业资料支撑。这些技术具备组合成智能植保系统的条件。

### 2. 传统植保方式痛点

传统植保流程主要存在以下问题：

- 虫情发现依赖人工巡查，效率受人员经验和巡查频次影响。
- 害虫识别依赖人工知识，普通农户难以准确区分相似虫害。
- 农药选择依赖经验，可能出现作物不匹配、防治对象不匹配或过量用药。
- 喷洒作业容易受天气影响，风速、降雨和温度条件如果判断不足，会降低防治效果并增加环境风险。
- 作业过程缺少结构化记录，后续难以追溯“为什么用药、用了什么药、是否安全、是否完成作业”。

这些问题使农业植保迫切需要一套能够将识别、决策、安全审计、执行和记录统一起来的智能系统。

### 3. 农药安全与合规需求

农药使用安全是智慧植保系统必须面对的关键问题。AI 可以快速生成建议，但如果缺少后置审计，模型可能输出来源不明确、作物不适配、防治对象不匹配或风险较高的药剂建议。对于连接无人机执行的系统而言，风险更高：一旦错误建议直接进入喷洒执行，就可能造成农作物损伤、环境污染或作业安全问题。

因此，牧野项目将“农药安全合规推理链”作为核心创新点。系统不允许 AI 决策直接驱动无人机，而是在 AI 决策后加入安全审计环节，对知识来源、作物适配、防治对象、毒性风险和天气条件进行检查，并将结果分为 `passed`、`warning` 和 `blocked`。合规状态直接控制无人机执行权限，使系统具备“能建议、能审计、能拦截、可追溯”的能力。

### 4. 真实无人机接入价值

很多竞赛项目停留在界面动画或单点模型展示，缺少与真实设备的工程连接。牧野项目引入 DJI Matrice 300 RTK 作为真实无人机接入型号，并通过 DJI OSDK 后端能力实现设备连接、状态获取、遥测读取和任务执行接口扩展。同时，系统保留 PX4 SITL 作为稳定仿真链路，保证在无硬件或现场受限条件下仍可完整演示。

这种“真机接入 + 仿真兜底”的架构可以证明项目具备从竞赛原型走向真实农业作业的工程延展性。

## 三、需求分析

### 1. 竞赛展示需求

项目面向大学生创新竞赛、挑战杯、计算机设计大赛等场景，需要在有限时间内向评委展示系统完整性、技术创新性和工程落地能力。竞赛展示需要满足：

- 10 到 15 分钟内完成端到端演示。
- 演示流程清晰，评委能看懂每一步系统行为。
- 能突出项目不是单点模型，而是完整智慧植保闭环。
- 能展示 AI 决策依据、合规审计过程和无人机执行状态。
- 在无外网或硬件受限环境下仍能稳定演示。

### 2. 农业应用需求

从农业应用角度，系统需要解决以下问题：

- 快速识别农田害虫类型。
- 结合天气、作物和农业知识生成防治建议。
- 降低农药误用和不安全作业风险。
- 支持无人机植保任务规划和执行状态回传。
- 留存作业记录，便于后续管理和复盘。

### 3. 安全需求

由于系统涉及农药建议和无人机执行，安全需求是项目的重要边界：

- AI 输出必须结构化校验，不能直接信任自由文本。
- 推荐药剂必须经过合规审计。
- 风险场景必须进入人工确认或禁止执行。
- 无人机真机执行应具备仿真验证和人工控制边界。
- 竞赛现场应优先保证演示安全和稳定。

### 4. 工程需求

系统需要具备持续开发和扩展能力：

- 前后端分离，便于界面和后端独立迭代。
- 业务模块按 detection、decision、drone、infra 分域组织。
- 外部服务不可用时具备降级能力。
- 支持本地部署、一键启动和离线演示。
- 测试覆盖核心链路，降低演示前回归风险。

## 四、总体方案设计

### 1. 总体架构

项目采用前后端分离、领域模块化、混合存储和可插拔无人机后端的总体架构。

```text
frontend/ 指挥大屏
  -> app/ FastAPI 应用编排层
  -> modules/detection 害虫检测
  -> modules/decision AI 决策与 RAG
  -> modules/drone 无人机控制与任务规划
  -> modules/infra 天气、事件、存储、日志
  -> data/ SQLite、JSONL、ChromaDB、样例数据
```

系统通过应用编排层统一调度各业务模块，避免检测、决策、无人机等领域相互强耦合。实时过程通过事件总线输出给前端，结构化结果写入 SQLite，知识数据通过 ChromaDB 向量库支持 RAG 检索。

### 2. 业务流程

```text
图片输入
  -> YOLO 害虫检测
  -> 天气与农田上下文采集
  -> RAG 农业知识检索
  -> AI 决策 / 多专家会诊
  -> 农药安全合规推理链
  -> 航线与喷洒参数规划
  -> 人工确认或自动执行
  -> PX4 仿真或 DJI Matrice 300 RTK 真机链路
  -> 大屏展示与报告生成
```

### 3. 数据流设计

系统数据从图片输入开始，经过检测结果、天气快照、RAG 检索上下文、AI 决策结果、合规审计结果、任务规划结果和无人机执行状态，最终汇总为任务记录和报告。

关键数据包括：

- 检测数据：害虫类型、置信度、检测框、标注图片。
- 天气数据：风速、降雨、温度、湿度等作业约束条件。
- 决策数据：推荐药剂、用量、理由、农事建议。
- 合规数据：检查项、风险等级、证据来源、执行策略。
- 无人机数据：后端类型、连接状态、遥测状态、任务进度。
- 追溯数据：任务事件、报告摘要、历史案例。

### 4. 仿真与真机双链路设计

系统采用双链路无人机架构：

- PX4 SITL：用于稳定演示、飞行流程验证和无硬件场景兜底。
- DJI Matrice 300 RTK + DJI OSDK：用于真实无人机接入能力展示和后续实机联调。

两条链路通过统一 `DroneBackend` 抽象层接入上层业务。上层任务流程只关心“连接、执行、遥测、状态”，不直接依赖具体飞行平台。这使系统可以在配置层切换后端，而不需要重写业务流程。

## 五、功能模块详细设计

### 1. 害虫图像识别模块

害虫识别模块负责将农田图像转化为结构化虫情数据。系统通过本地 YOLO 推理服务完成目标检测，输出害虫类别、置信度和检测位置，同时生成标注图片用于前端展示。

模块特点：

- 模型服务与主流程解耦，便于单独调试和替换。
- 检测结果统一转换为标准结构，降低后续模块处理复杂度。
- 支持样例图片演示和后续实时图像流扩展。
- 检测完成后发布事件，前端可实时更新流程状态。

### 2. RAG 农业知识库模块

RAG 模块负责为 AI 决策提供农业知识上下文。知识库包含农药目录、作物信息、害虫同义词、历史决策案例和农业知识文档。系统根据害虫类型和作物信息检索相关条目，并拼接进决策上下文。

模块特点：

- 支持农药知识、历史案例和农业知识多类型检索。
- 支持中英文害虫标签归一化，提高演示场景命中率。
- 检索失败时不阻塞主流程，可降级为基础决策。
- 后续任务结果可沉淀为新的历史案例，形成知识闭环。

### 3. 多专家 AI 决策模块

AI 决策模块负责生成防治建议。系统支持快速专家路径和多智能体会诊路径。对于熟悉场景，系统可调用快速专家路径降低延迟；对于陌生或不确定场景，系统可调用昆虫学家、农学家、植保专家等角色进行多专家会诊。

模块特点：

- 使用结构化 prompt 和 schema 校验提高输出稳定性。
- 支持多模型、多角色并行推理。
- 支持专家投票、置信度计算和分歧提示。
- 专家路径失败时可自动升级到多智能体会诊。

### 4. 农药安全合规推理链模块

合规推理链是项目的核心创新模块。它位于 AI 决策之后、无人机执行之前，对推荐药剂进行后置审计。

第一版固定五项检查：

- 来源可信度：药剂是否来自 RAG 知识库或结构化目录。
- 作物适配：药剂是否适用于当前作物。
- 防治对象适配：药剂是否覆盖当前害虫。
- 安全等级：是否存在高毒、禁限用或不适合演示场景的风险。
- 天气约束：当前风速、降雨、温度是否适合喷洒。

合规结果直接影响执行策略：

- `passed`：允许继续执行。
- `warning`：强制人工确认。
- `blocked`：禁止无人机进入喷洒执行。

模块输出不仅包含状态，还包含风险原因、证据来源、命中规则和执行影响，使前端和报告可以直接展示“为什么通过、为什么警告、为什么拦截”。

### 5. 无人机任务规划模块

任务规划模块负责将 AI 决策结果转换为无人机可执行的作业参数，包括飞行路径、覆盖区域、飞行高度、飞行速度、喷洒速率和任务阶段。该模块将“农业决策”转化为“无人机任务”，是 AI 系统与执行系统之间的桥梁。

模块特点：

- 根据地块、天气和防治建议生成作业参数。
- 与合规推理链联动，风险场景不进入执行阶段。
- 输出可供 PX4 仿真和真实无人机后端复用的任务结构。

### 6. DJI Matrice 300 RTK 真机接入模块

项目已经以 DJI Matrice 300 RTK 作为真实无人机接入型号，建设 DJI OSDK 后端能力。该模块用于真实设备连接、状态获取、遥测读取和任务执行接口扩展。

模块特点：

- 通过 `DroneBackend` 抽象层接入，不影响上层业务流程。
- 支持真机连接状态、飞行状态、位置信息、电量等遥测数据扩展。
- 与 PX4 仿真后端保持一致的接口形态。
- 竞赛现场可根据条件选择真机能力展示或仿真链路演示。

### 7. PX4 SITL 仿真模块

PX4 SITL 用于无人机飞行流程仿真和演示保障。在无真实无人机、无飞行场地或安全受限情况下，系统仍可通过 PX4 SITL 展示从任务规划到飞行执行的完整闭环。

模块特点：

- 支持连接、任务启动、任务进度和状态回传。
- 可与前端地图态势联动展示飞行过程。
- 作为真机链路的安全回退方案。

### 8. 可视化指挥大屏模块

前端大屏负责将复杂的系统流程转化为评委可理解的可视化界面。大屏展示内容包括害虫检测结果、天气数据、AI 决策、RAG 证据、合规审计、无人机状态、地图态势、任务历史和事件日志。

展示重点：

- 展示端到端流程，而不是孤立模块。
- 展示 AI 决策依据，而不是只显示结论。
- 展示合规推理链，让安全创新点可见。
- 展示无人机状态，突出系统与真实设备的连接能力。

### 9. 任务追溯与报告生成模块

系统通过 JSONL 事件流和 SQLite 结构化存储记录完整任务过程。任务完成后，系统可生成报告，包含识别结果、天气信息、AI 建议、合规审计、无人机执行状态和任务结论。

模块价值：

- 支持竞赛答辩材料生成。
- 支持任务复盘和历史查询。
- 支持后续形成历史案例库，反哺 RAG 检索。

## 六、关键技术与实现路径

### 1. YOLO 害虫检测

系统使用 YOLO 完成害虫目标检测，适合在图片中定位虫害目标并输出置信度。通过独立 YOLO API 服务，检测模型可以单独部署、调优或替换，主流程只依赖稳定的检测结果结构。

### 2. RAG 检索增强

系统使用向量检索将农药目录、历史案例和农业知识引入 AI 决策。相比仅依赖大模型内部知识，RAG 可以提高农业建议的依据性，并让前端展示知识来源。

### 3. 多智能体专家会诊

系统将复杂植保决策拆分为多专家角色协同判断。不同专家角色从害虫识别、作物生长、药剂选择和作业风险等角度给出意见，再通过投票和置信度机制汇总。

### 4. 合规规则审计

系统用规则链约束 AI 输出，重点检查来源、作物、防治对象、安全等级和天气条件。规则链不替代正式法规系统，但在竞赛原型中可以有效证明“AI 决策进入执行前必须经过安全审计”的工程思想。

### 5. DroneBackend 无人机后端抽象

系统通过 `DroneBackend` 抽象层统一无人机后端能力，将 PX4 SITL、DJI OSDK 和后续 DJI Cloud API 纳入同一接口体系。该设计降低了平台切换成本，也提高了系统的工程扩展能力。

### 6. FastAPI + React 工程架构

后端使用 FastAPI 进行 API 编排和异步任务处理，前端使用 React、Vite 和 TypeScript 构建可视化指挥大屏。前后端分离使系统展示层和业务逻辑可以独立迭代。

### 7. SQLite + JSONL + ChromaDB 数据体系

系统采用混合存储策略：

- SQLite：存储任务、检测、天气、决策、无人机状态等结构化数据。
- JSONL：记录事件流，支持实时展示和回放。
- ChromaDB：存储向量知识库，支持 RAG 检索。

这种组合适合竞赛和本地部署场景，具有零运维、可移植、易演示的特点。

## 七、项目创新点

### 1. AI 决策后置安全合规审计

系统不让大模型直接控制无人机喷洒，而是在 AI 决策之后加入农药安全合规推理链。该推理链根据知识来源、作物适配、防治对象、毒性风险和天气条件对建议进行审计，使 AI 决策具备工程安全边界。

### 2. RAG 与规则链结合的可解释农药推荐

系统将 RAG 检索结果与合规规则结合，不仅输出“推荐什么药”，还输出“为什么推荐、依据来自哪里、风险在哪里、是否允许执行”。这使农药推荐从文本生成升级为可解释的结构化决策。

### 3. 多专家智能体会诊与分歧处理

系统引入昆虫学、农学、植保等专家角色，通过多模型并行推理和投票机制形成决策结果。当场景不确定或专家意见存在差异时，系统可进行升级会诊和风险提示，提高复杂场景下的决策可靠性。

### 4. 真实无人机与仿真统一控制架构

系统通过 `DroneBackend` 抽象层统一无人机控制接口，既支持 PX4 SITL 仿真，也已接入面向 DJI Matrice 300 RTK 的 DJI OSDK 真实无人机后端能力。该架构使项目从竞赛演示平滑过渡到真实设备联调，避免系统停留在纯动画或纯仿真层面。

### 5. 从识别到执行的端到端闭环

系统覆盖虫情识别、知识检索、AI 决策、合规审计、航线规划、无人机执行和结果追溯，形成完整业务闭环。相比单点模型展示，该项目更能体现智慧农业系统工程能力。

### 6. 离线可演示的工程化竞赛方案

系统考虑竞赛现场网络、硬件和时间限制，提供一键启动、样例场景、mock 数据、仿真链路和报告生成能力，使项目不仅“能开发”，也“能稳定展示”。

## 十三、风险分析与保障措施

### 1. 外部 API 不稳定

风险：天气 API、大模型 API 或 Embedding 服务可能在现场不可用。

保障：系统支持缓存、mock 数据和离线演示路径；RAG 检索失败时可降级到基础决策流程。

### 2. 大模型输出不确定

风险：大模型可能输出格式异常或建议不稳定。

保障：系统使用结构化 schema 校验、重试机制、多专家会诊和合规推理链，降低单次模型输出风险。

### 3. 真实无人机现场环境复杂

风险：真实无人机受场地、权限、电量、定位、SDK 环境和安全要求影响，竞赛现场可能无法完整真机飞行。

保障：系统保留 PX4 SITL 作为稳定演示链路，DJI Matrice 300 RTK 真机接入作为工程能力展示；在具备安全条件时可切换真机后端，在受限场景下使用仿真链路完成全流程展示。

### 4. 农药合规数据边界

风险：农药登记、禁限用规则和地方政策具有时效性，完整法规判断复杂。

保障：当前阶段定位为竞赛原型与安全审计机制展示，使用结构化目录、RAG 知识和规则链完成可解释风险判断；后续可接入权威农药登记数据库和正式规则引擎。

### 5. 演示稳定性

风险：竞赛演示时间短，现场操作容错空间小。

保障：系统提供一键启动脚本、固定演示场景、人工确认节点、WebSocket 断线降级和任务报告生成能力，降低现场不确定性。

### 6. 设备安全与飞行合规

风险：真实无人机涉及飞行安全、场地许可、操作者资质和设备状态，不能在不满足条件的场景下强行飞行。

保障：项目将真实无人机接入能力与现场实际飞行分开处理。竞赛现场优先使用仿真链路展示闭环，在安全条件满足时再展示 DJI Matrice 300 RTK 真机连接和状态读取能力。

## 十五、竞赛展示方案

### 1. 展示主线

竞赛展示围绕一条主线展开：

```text
发现虫害 -> AI 给出防治建议 -> 合规推理链审计风险 -> 无人机执行或拦截 -> 生成报告
```

这条主线能让评委理解系统的完整价值：牧野不是简单识别虫子，而是把识别结果变成可审计、可控制、可追溯的农业作业流程。

### 2. 典型演示场景

安全通过场景：

- 作物、害虫、药剂和天气均匹配。
- 合规结果为 `passed`。
- 系统继续进入无人机任务流程。

风险确认场景：

- 药剂基本可用，但存在天气风险或证据不足。
- 合规结果为 `warning`。
- 系统强制进入人工确认。

执行拦截场景：

- 药剂不适配作物或防治对象，或存在明显安全风险。
- 合规结果为 `blocked`。
- 系统禁止无人机喷洒任务。

### 3. 答辩表达重点

- 系统是端到端闭环，而不是单点模型。
- AI 决策有 RAG 知识依据，不是纯生成文本。
- AI 决策后有合规推理链，不会直接控制无人机。
- 合规结果直接约束无人机执行权限。
- 系统已具备 DJI Matrice 300 RTK 真机接入能力，并通过 PX4 SITL 保证现场稳定演示。
