# 昆虫热力图产品化执行计划

> 在单块田地范围内，将现有的任务内相对热力图扩展为可保存、可筛选、可对比、可驱动作业的虫情数据产品。

## 状态

- 状态：进行中（产品化与自动化已完成，仅待真实模型容器验收）
- 优先级：高
- 创建日期：2026-08-04
- 产品规格：[昆虫热力图产品规格](../product-specs/insect-heatmap.md)

## 已确定的决策

1. 当前只做一个活动田地，不接省级行政地图。
2. 田地边界可以虚拟化，虫情数据必须来自后端 YOLO 或明确标记的演示种子。
3. 当前 `density` 是单次任务内的相对热值，不包装成绝对虫口密度。
4. 热力图保持常量；新巡检快照到达时才整体更新。
5. 先完善数据可追溯性，再增加筛选、趋势和喷洒前后对比。

## 当前基线

- YOLO 检测框已携带坐标空间和原图尺寸。
- 后端已生成 8×10 相对热力网格、来源元数据和变量喷洒速率表。
- SQLite 已通过独立巡检批次、检测项和热力快照表保存 `density_grid`、`density_metadata` 与算法版本。
- HTTP API 已提供最新快照、组合筛选列表、快照详情和喷洒前后配对查询。
- 前端已使用 Three.js 展示单块虚拟田地，并保留最后有效工作流帧。
- 首页已支持虫种子集热力与快照时间标识；历史页已支持组合筛选、三项趋势、快照网格和喷洒前后静态对比。
- 演示种子和真实 YOLO 数据已经具有可区分的来源标记。

## 当前缺口

- 当前任务内归一化值不能直接用于跨时间绝对比较。
- 每条喷洒迭代已显式记录其消费的 `snapshot_id`、算法版本和喷洒计划；复检快照可驱动下一轮变量喷洒。
- 1366×768、1920×1080 和 1920@125% 等效区域已通过真实 Chromium 布局契约，截图与失败 trace 接入 CI。
- Docker 配置、隔离冒烟栈和 CI 入口已完成；当前执行环境无 Docker，仍需外部实跑以及真实模型容器验收。

## 数据需求

- 至少三类昆虫、每类若干张带 YOLO 检测结果的固定巡检图片。
- 同一田地喷洒前后成对样本，用于验证对比展示，不用于宣称真实药效。
- 若要进一步计算绝对虫口密度，需要采样面积、飞行高度、相机参数或正射影像地理变换。

## 完成定义

- 产品规格、数据模型、API 和前端术语一致。
- 固定巡检输入能够生成可重复的热力快照。
- 快照能被保存、筛选、恢复并与喷洒/复检关联。
- 页面明确显示数据来源和相对热值语义。
- 不存在随机虫情、省级地图或未标记的模拟数据。
